Boss Loops Cloud runs decision loops for your organization. Better Data operates the service. You integrate with the [Cloud API](/docs/cloud/api-reference) and approve in the product.

## What you get

- **Organization isolation.** An API key and a signed-in user only read and change loops for their own organization. Another organization's loop id is not found.
- **Organization API keys** for integrations. Keys are shown once, can be rotated (previous secret valid for 24 hours), and can be revoked immediately. A key cannot administer other keys.
- **Actor class on each API call.** Send `X-Actor-Type: user`, `system`, or `llm`. The class cannot be overridden by the transition body, and a key cannot act as a named person.
- **Approver assignments.** A human approval transition runs only when that person has an approver assignment on the decision loop. When the assignment has a limit, the decision amount must be within it. Missing configuration fails closed: the transition is not recorded.
- **History.** `GET /api/v1/loops/{aggregateId}/history` returns the recorded transitions, including who acted.

Commercial metering and tier limits are enforced by the service. Numeric quotas are part of your agreement, not a fixed value in this guide. See [Pricing](/pricing).

## What to use the API for

| Action | Route |
| --- | --- |
| See which loop definitions your organization can run | `GET /api/v1/loops/catalog` |
| Open a decision loop | `POST /api/v1/loops` |
| Advance it | `POST /api/v1/loops/{aggregateId}/transition` |
| Stop it | `POST /api/v1/loops/{aggregateId}/cancel` |
| Read what happened | `GET /api/v1/loops/{aggregateId}/history` |

Details, including which actor class can complete a transition, are in the [API reference](/docs/cloud/api-reference).

## Approvals

Protected approvals are transitions whose signal id is an approve signal (it contains `.approve.` or ends in `.approve` or `.approve.v1`). The person approving must be signed in and assigned as an approver. Integrations should open the loop and attach evidence. They should not send a person's identity in `actor.id` and expect that person to be the approver of record.

## Connectors

Slack approvals and Google Sheets applies are configured in the Boss Loops application for your organization. The open-source runtime does not include those hosted connectors. See [Getting started](/docs/cloud/getting-started).

## Self-hosted

The same decision-loop model can run in your process with `@loop-engine/sdk`. Isolation, keys, and approver assignments above are Cloud behavior. Self-hosted actor checks are the transition `actors` list and `canActorExecuteTransition` in `@loop-engine/actors`. See [Installation](/docs/getting-started/installation).
