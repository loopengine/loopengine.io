## Loop definition YAML reference

This format is validated by `LoopDefinitionSchema` in `@loop-engine/core` via `parseLoopYaml` (`@loop-engine/loop-definition`).

### Top-level fields

- `id: string` (required)
- `version: string` (required; published examples use semver, and the schema accepts any string)
- `name: string` (required)
- `description: string` (required)
- `domain?: string`
- `states: StateSpec[]` (required)
- `initialState: string` (required, must exist in `states`)
- `transitions: TransitionSpec[]` (required)
- `outcome?: OutcomeSpec` (when present, `businessMetrics` must be a non-empty array)
- `tags?: string[]`
- `metadata?: Record<string, unknown>`

### `StateSpec`

- `id: string` (required)
- `label: string` (required)
- `description?: string`
- `isTerminal?: boolean`
- `isError?: boolean`

### `TransitionSpec`

- `id: string`
- `from: string`
- `to: string`
- `signal?: string` (defaults to `id`)
- `actors: ("human" | "automation" | "ai-agent" | "system")[]` (required, at least one)
- `guards?: GuardSpec[]`
- `description?: string`
- `metadata?: Record<string, unknown>`

`allowedActors` is not a field on the current schema. Definitions that still use it fail validation.

### `GuardSpec`

- `id: string`
- `description: string`
- `severity: "hard" | "soft"`
- `evaluatedBy: "runtime" | "module" | "external"`
- `failureMessage?: string`
- `parameters?: Record<string, unknown>`

### `OutcomeSpec`

- `description: string`
- `valueUnit: string`
- `businessMetrics: BusinessMetric[]` (required and non-empty when `outcome` is set)
- `id?: string`
- `measurable?: boolean`

## Annotated example (`scm.procurement`)

```yaml
id: scm.procurement
version: 1.0.0
name: Procurement
domain: scm
description: Purchase order lifecycle through settlement

states:
  - id: OPEN
    label: Open
  - id: PO_CONFIRMED
    label: PO confirmed
  - id: RECEIVED
    label: Received
  - id: INVOICE_MATCHED
    label: Invoice matched
  - id: SETTLED
    label: Settled
    isTerminal: true
  - id: DISPUTED
    label: Disputed
    isError: true

initialState: OPEN

transitions:
  - id: confirm_po
    from: OPEN
    to: PO_CONFIRMED
    actors: [human, automation, ai-agent]
    guards:
      - id: approval_obtained
        severity: hard
        evaluatedBy: external
        description: PO must be approved before confirmation
        failureMessage: PO confirmation requires explicit approval

outcome:
  id: po_settled
  description: Purchase order settled with matched invoice
  valueUnit: po_settled
  measurable: true
  businessMetrics:
    - id: cycle_time_days
      label: PO cycle time (days)
      unit: days
      improvableByAI: true
```

## Common validation errors

- `initialState` not found in `states`
- transition `from`/`to` references an unknown state
- missing `actors`, or `actors` empty
- missing `name`, or a state missing `label`
- `outcome` present without a non-empty `businessMetrics` array
- duplicate state ids
