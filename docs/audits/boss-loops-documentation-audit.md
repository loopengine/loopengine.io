# Boss Loops documentation audit

Date: 2026-10-24

This inventory records what the public docs claimed, what the implementation supports, and the action taken. It is not published on bossloops.io. Customer-facing pages were updated from this evidence. Application code was not changed.

## Architecture

| Question | Finding |
| --- | --- |
| Documentation source | Hand-written MDX in `betterdata-sites/bossloops.io/content/docs`, loaded by `lib/docs` and ordered by `content/docs/**/_meta.json`. Not generated from OpenAPI. |
| GitHub repository and branch | `loopengine/loopengine.io`, branch `main`. Local checkout is one commit ahead of `origin/main` (pricing copy, unrelated to docs). |
| Deployment | Vercel project `web-loopengine-io` serves `bossloops.io` and `www.bossloops.io`. `loopengine.io` redirects to the brand site (`middleware.ts`). The hosted product is a different Vercel project (`bossloops` / `app.bossloops.io`). |
| Published vs source | Live sitemap (2026-10-24) lists the same doc routes as `content/docs`. Sitemap `lastmod` is 2026-07-30, so production is the docs source from before this audit. |
| Other sites | `docs.betterdata.co` has Boss Loops pages that linked here and, in several cases, described an older hosted service. Those pages are a separate git repo (`docs.betterdata.co`, `main`). |

## Source of truth

Hosted behavior was read from `betterdataco/bossloops` **`origin/main`** at `005b7d9` (2026-09-25, merge of transition-authority work). The local Boss Loops checkout is on `demo` and its auth files differ from `main`. That working tree was not treated as production.

Open-source behavior was read from `loopengine/loop-engine` `main` and from npm on 2026-10-24 (`@loop-engine/sdk@1.0.0-rc.1`, most other cited 1.0 packages `@1.0.0-rc.0`, `adapter-kafka@0.1.7`, `adapter-postgres@0.2.0`).

Customer docs describe an organization and its API key. They do not describe internal platform tenancy, session minting, or operator-only routes.

## Release classification

**PASS WITH EXCEPTIONS.** The public Cloud and schema corrections match `origin/main` and the published packages. Exceptions are listed in the change summary: engine-repo YAML still on the old field, a system-classified API key cannot transition, the in-app API narrative is still stale, and a second pass is still needed on adapter pages that were only scanned.
